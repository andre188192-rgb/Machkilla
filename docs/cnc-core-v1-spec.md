# Техническое задание: CNC Core v1.0 (2026)

## 1. Введение и цели проекта

### 1.1. Назначение

Разработка высокопроизводительного, стабильного, расширяемого программного обеспечения для управления станками с ЧПУ, превосходящего существующие решения (Mach3/Mach4, LinuxCNC) по точности, гибкости и функциональности, с поддержкой современного аппаратного обеспечения и облачной экосистемы.

### 1.2. Ключевые принципы

- Детерминированность и реальное время: гарантированное время отклика ≤ 25 мкс на уровне драйверов/контроллера.
- Модульность и расширяемость: поддержка плагинов, скриптов, пользовательских модулей.
- Кросс-платформенность: нативные приложения для Windows 11/12, Linux (Ubuntu LTS, Fedora), macOS (поддержка M‑серии).
- Производительность: поддержка > 12 осей, включая управление роботами‑манипуляторами и кинематику 5+2, 6 осей.
- Открытость и совместимость: поддержка G‑кода (ISO, Fanuc, Heidenhain), открытые API, обратная совместимость с протоколами популярных контроллеров (EtherCAT, Modbus TCP, USB, PCIe).

## 2. Архитектурные требования

### 2.1. Многослойная архитектура

1. **Верхний уровень (UI/UX)**
   - Графический интерфейс на Qt6/QML или современном фреймворке (возможно, Vulkan для 3D).
   - Веб‑интерфейс для удаленного управления через браузер.
   - Поддержка AR/VR для визуализации процесса обработки.
2. **Уровень планировщика траектории (Trajectory Planner)**
   - Аппаратно‑независимый планировщик с lookahead > 1000 блоков.
   - Поддержка адаптивного управления скоростью по данным датчиков (вибрация, нагрузка).
   - Режимы: Constant Velocity (CV), Exact Stop, Adaptive Smoothing (AI‑based).
   - Формирование профилей движения (S‑кривые, адаптивные полиномы 7‑го порядка).
   - Выходные данные: поток дискретных позиций с привязкой к системному времени.
3. **Уровень связи (Communication Layer)**
   - Менеджер плагинов для драйверов контроллеров.
   - Буферизация данных (FIFO) с глубиной, адаптируемой под пропускную способность канала.
   - Приоритизация команд (аварийный стоп, пауза, коррекции).
   - Шифрование и проверка целостности данных при передаче.
4. **Аппаратный уровень (Controller Hardware)**
   - Поддержка внешних контроллеров с FPGA, микроконтроллерами (STM32, ESP32), SoC (Raspberry Pi CM4).
   - Аппаратная генерация импульсов Step/Dir, PWM, управление сервоприводами.
   - Прямая работа с энкодерами, датчиками температуры, давления.
   - Локальный обработчик прерываний для экстренных ситуаций.

### 2.2. Требования к производительности

- Частота планирования траектории: до 10 кГц.
- Максимальная частота импульсов: 10 МГц на канал.
- Джиттер импульсов: < 10 нс (при использовании внешнего контроллера с FPGA).
- Задержка от команды до исполнения: < 1 мс.

## 3. Функциональные требования

### 3.1. Базовый функционал

- Интерпретатор G‑кода с поддержкой макросов, циклов, подпрограмм.
- Визуализация 3D‑траектории в реальном времени с возможностью изменения угла обзора.
- Редактор G‑кода с подсветкой синтаксиса, автодополнением.
- Управление шпинделем, охлаждением, периферией.
- Калибровка осей, настройка кинематики (дельта, гексапод, портальные схемы).
- Симуляция обработки с обнаружением коллизий.

### 3.2. Расширенные функции

- AI‑оптимизатор траекторий: анализ модели детали и выбор оптимального порядка обработки, минимизация холостых ходов.
- Адаптивное управление: коррекция скорости и глубины резания по данным акселерометров, датчиков силы, микрофонов (контроль вибрации).
- Прогностическое обслуживание: оценка износа инструмента, предупреждение о поломке.
- Облачная синхронизация: хранение проектов, библиотек инструментов, настроек станков в облаке. Возможность удаленного мониторинга нескольких станков через дашборд.
- Голосовое управление и обратная связь (для операторов в условиях зашумленности).
- Поддержка цифровых двойников (Digital Twin): синхронизация виртуальной модели станка с реальным для тестирования программ без риска поломки.

### 3.3. Безопасность

- Многоуровневая система паролей (оператор, наладчик, инженер).
- Аварийные контуры (программный, аппаратный).
- Запись логов всех действий для расследования инцидентов.
- Шифрование критичных данных (например, запатентованных G‑кодов).

## 4. Требования к разработке

### 4.1. Технологический стек

- Языки программирования: C++20 (ядро), Python (для скриптов и AI‑модулей), Rust (критичные к безопасности компоненты).
- Графический интерфейс: Qt6, WebAssembly (для веб‑версии).
- Базы данных: SQLite (локально), возможность подключения к PostgreSQL/облачным БД.
- Сетевые протоколы: HTTPS/WebSockets (для облака), EtherCAT, PROFINET, MQTT (для IoT‑датчиков).
- Контейнеризация: критичные компоненты в Docker‑контейнерах для изоляции и стабильности.

### 4.2. Документация и API

- Полная документация для пользователей и разработчиков.
- OpenAPI спецификация для облачных сервисов.
- SDK для создания плагинов и кастомизации интерфейса.
- Примеры кода, симуляторы для тестирования.

### 4.3. Тестирование и отладка

- Модульное и интеграционное тестирование всех компонентов.
- Использование симуляторов станков для отладки без аппаратуры.
- Стресс‑тесты на длительную (неделю) непрерывную работу.
- Тестирование на разных ОС и конфигурациях железа.

## 5. План разработки (Roadmap)

### Этап 1 (6 месяцев): Прототип ядра

- Разработка планировщика траекторий и интерпретатора G‑кода.
- Создание базового графического интерфейса.
- Поддержка одного типа контроллера (например, Ethernet).

### Этап 2 (6 месяцев): Альфа‑версия

- Реализация основных функций управления.
- Интеграция с облачным сервисом (базовый функционал).
- Тестирование на реальном оборудовании.

### Этап 3 (6 месяцев): Бета‑версия

- Добавление расширенных функций (AI‑оптимизация, адаптивное управление).
- Поддержка дополнительных контроллеров и протоколов.
- Оптимизация производительности.

### Этап 4 (3 месяца): Релиз и поддержка

- Исправление багов, финальная оптимизация.
- Выпуск документации.
- Запуск программы обратной связи с пользователями.

## 6. Критерии приемки

1. Стабильность: бесперебойная работа в течение 168 часов (неделя) на производственном станке.
2. Точность: погрешность позиционирования не превышает заданную в настройках (доказуемо тестами лазерным интерферометром).
3. Производительность: достижение заявленных характеристик по частоте импульсов, lookahead и времени отклика.
4. Безопасность: отсутствие уязвимостей, проверенное независимым аудитом.
5. Юзабилити: положительные отзывы от фокус‑группы операторов и наладчиков.

## 7. Дополнительные рекомендации

- Рассмотреть возможность open‑source релиза ядра для ускорения развития экосистемы.
- Создать маркетплейс плагинов и профилей станков.
- Обеспечить поддержку legacy‑оборудования (параллельный порт LPT) через переходные адаптеры.
- Реализовать систему автоматических обновлений с откатом при неудаче.
